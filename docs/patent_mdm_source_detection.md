# [특허 기초자료] 카메라 차단 출처 판별 방법 및 오판 방지 기술

> 변리사 상담용 기초자료입니다. 법률적 판단(신규성·진보성·등록가능성)은 변리사 검토가 필요합니다.
> 본 문서는 "발명의 기술적 특징"을 정리한 것으로, 그대로 청구항이 되는 것은 아닙니다.

---

## 1. 발명의 명칭 (안)
"모바일 단말의 카메라 차단 출처를 판별하는 방법 및 장치, 그리고 해제 전이(轉移) 중 모순 상태의 오판 방지 방법"

## 2. 기술 분야
모바일 단말(iOS/Android) 보안 제어(MDM/카메라 통제) 분야. 자사 보안앱과 타사 관리 프로파일(MDM)이 공존하는 환경에서, **카메라 등 하드웨어 기능을 누가 차단했는지**를 단말 스스로 판별하는 기술.

---

## 3. 배경기술 및 해결 과제

### 종래기술의 문제
- 자사 보안앱(예: 카메라 차단 MDM)은 단말의 카메라가 "막혀 있음"만 알 수 있고, **그 차단이 자사에 의한 것인지, 이미 설치된 타사 MDM/관리 프로파일에 의한 것인지 구별하지 못함.**
- 이로 인해:
  - (a) 타사 MDM이 막은 것을 **자사 차단으로 오인** → 정상 동작으로 착각
  - (b) 자사가 차단을 **해제하는 전이 과정**에서, 해제 프로파일이 아직 완전히 적용되지 않아 카메라가 일시적으로 막혀 있는 **모순 상태**를, "타사 MDM 차단" 또는 "비정상 사용"으로 **오판** → 사용자가 부당하게 차단 화면에 갇히거나 잘못된 경고를 받음

### 해결하려는 과제
1. 카메라 차단의 **출처(자사 / 타사 / 없음)를 단말에서 자동 판별**
2. **해제 전이 중 모순 상태**를 타사 차단/비정상으로 오판하지 않도록 배제
3. OS가 "어느 앱이 막았는지" 직접 알려주지 않는 제약 하에서 수행

## 4. 발명의 핵심 구성 (기술적 특징)

### 특징 A — 이중 신호 조합에 의한 출처 판별
단말이 다음 **두 독립 신호**를 취득하여 조합한다:
1. **하드웨어 제한 신호**: OS로부터 카메라가 "정책적으로 제한됨(restricted)" 상태인지 취득
   - iOS: `AVCaptureDevice.authorizationStatus(for: .video) == .restricted`
   - Android(Knox): `restrictionPolicy.isCameraEnabled()` 의 부정
   - ※ 사용자가 거부한 상태(denied)와 **정책 제한(restricted)** 을 구분하는 것이 포인트
2. **자사 제어주체 신호**: 자사 보안 프로파일이 단말에 설치·신뢰되어 있는지 취득
   - iOS: 자사 프로파일에 포함된 **인증서를 X.509 신뢰 평가**(`SecTrustEvaluateWithError`)하여, 신뢰 성공 시 자사 프로파일 설치로 판정
   - Android: 자사 앱이 디바이스 관리자(admin)·Knox 라이선스로 활성 제어 중인지

**판정 규칙:**
```
카메라 제한됨(restricted) == 참 이고:
    자사 제어주체 == 참  → 자사(GateON) 차단
    자사 제어주체 == 거짓 → 타사(other) MDM 차단
카메라 제한됨 == 거짓 → 차단 없음
```

### 특징 B — 단말 상태값 조합에 의한 "해제 전이 중 모순 상태" 오판 방지 (핵심)
특징 A만으로는, **해제 진행 중** 자사 프로파일 신뢰가 일시적으로 유지/소실되는 과도기에 오판이 발생한다. 이를 막기 위해 **단말에 저장된 자사 제어 상태값을 추가로 조합**한다.

- **차단 의도 상태값**(profile_status): `disable`(차단), `enable`(해제 시도), `wait`(전이 대기)
- **차단 완료 기록**(profileInstalled): 자사가 서버에 "차단 완료"를 보고했는지(`true`/`false`)

**정교화된 자사 차단 판정:**
```
자사차단(gateOnBlocking) =
    자사프로파일설치됨
    AND ( 차단의도 ∈ {disable, wait}      // 자사가 차단하려는 상태
          OR 차단완료기록 == true )        // 자사가 차단완료를 확정한 이력

타사MDM = 카메라제한됨 AND NOT 자사차단
```

**효과:** 해제 시도로 상태값이 `enable`로 바뀌었으나 해제 프로파일이 아직 미구성되어 카메라가 유지되는 **모순 구간**에서, `차단완료기록==true`를 함께 보아 **자사 차단으로 유지 판정** → 타사 MDM/비정상으로의 오판을 배제한다.

### 특징 C — 판별 결과에 따른 차등 사용자 응대
- 타사 MDM 차단으로 판별 → 자사 차단 화면/경고 대신 **"타사 보안앱에 의한 차단" 안내**로 전환하고, 자사 비정상(위반) 처리에서 제외
- 자사 차단 → 정상 차단 흐름 유지

## 5. 종래기술 대비 차별점 (진보성 주장 포인트)
1. OS가 차단 주체를 알려주지 않는 제약 하에, **하드웨어 제한 신호 + 자사 제어주체 신호**의 이중 조합으로 출처를 판별 (단순 "카메라 막힘 여부" 확인을 넘어섬)
2. iOS에서 **프로파일 설치 여부를 인증서 X.509 신뢰 평가로 판정**하는 구체적 수단
3. **해제 전이 중 모순 상태**라는 특정 장애 상황을, **복수의 단말 상태값(의도/완료기록) 조합**으로 배제하는 오판 방지 로직 — 단순 논리추론으로 도출되기 어려운 상태머신 기반 문제해결
4. 판별 결과에 따라 **비정상 처리 제외 + 차등 안내**로 연결되는 일련의 제어

## 6. 청구항 후보 (골격, 변리사와 정제 필요)
- **독립항 1 (방법)**: 카메라의 정책적 제한 여부를 취득하는 단계; 자사 보안 프로파일의 설치·신뢰 여부를 인증서 신뢰평가로 취득하는 단계; 상기 두 결과를 조합하여 차단 출처를 자사/타사/없음으로 판별하는 단계; 를 포함하는 카메라 차단 출처 판별 방법.
- **종속항**: 상기 판별 단계는, 단말에 저장된 차단 의도 상태값 및 차단 완료 기록을 추가로 조합하여, 해제 전이 중 카메라가 유지되는 모순 상태를 자사 차단으로 유지 판정함으로써 타사 차단 오판을 배제하는 것을 특징으로 함.
- **종속항**: iOS의 `restricted` 상태와 사용자 거부(`denied`)를 구별하여 정책 제한만을 차단으로 취급.
- **종속항**: Android Knox 환경에서 디바이스 관리자/라이선스 활성 여부로 자사 제어주체를 판정.
- **장치항/매체항**: 상기 방법을 수행하는 단말 장치 및 컴퓨터 판독가능 기록매체.

## 7. 도면(플로우) 개요
1. [입력] 카메라 정책제한 여부 취득 → 2. [입력] 자사 프로파일 신뢰평가 → 3. [입력] 단말 상태값(의도/완료기록) 취득 → 4. [판정] 자사차단 여부 산출 → 5. [분기] 자사/타사/없음 → 6. [응대] 타사면 안내 전환 및 비정상 제외 / 자사면 정상 차단 흐름
